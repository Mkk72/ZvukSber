# Ф0 — спайк: что проверено на живой машине

Дата: 13.11.2026. Хост `compprog2025`, Windows 11 Pro 10.0.26300.
Стект: Electron 45.3.1 (проверялся и 40.10.6), TypeScript 6, сборка `tsc` → `dist/`.

Пробник: `src/main/index.ts` (режимы `--login`, staged по умолчанию), инъекция —
`src/main/injection.ts`. Артефакты: `_spike/` (скриншоты, `boot.log`, `report-*.json`).

## 1. Electron на этой машине стартует только с `--no-sandbox`

| Проверка | Результат |
|---|---|
| Без флагов | падение до выполнения `main`: `0x80000003` / `0xC0000005` |
| `--disable-gpu` | так же |
| `--disable-gpu-sandbox` | так же |
| `--disable-gpu --disable-gpu-sandbox` | так же |
| `--disable-gpu-compositing` | так же |
| `--disable-crash-reporter` + свой `--user-data-dir` | так же |
| Запуск не из моей оболочки, а через WMI (`Win32_Process.Create`) | так же — значит дело не в песочнице DSH |
| `--no-sandbox` | **стартует и работает** |
| Electron 40.10.6 вместо 45.3.1 | то же падение |

Вывод: на этой машине Chromium-песочница Electron не поднимается ни в одном варианте,
при этом сам Chrome/Edge работают. Причина не в ASLR (Mandatory ASLR выключен), не в
crashpad и не в профиле. Лечится только `--no-sandbox`.

Практика: флаг держим в настройках приложения (`noSandbox: true` в конфиге этого хоста),
по умолчанию для других машин — песочница включена. Приложение грузит один доверенный сайт,
но записать это в README надо честно.

## 2. Сайт блокирует прокси, а не Electron

| Подключение | Внешний IP | Ответ zvuk.com |
|---|---|---|
| системный прокси WinINET `192.168.50.3:10801` | 205.196.80.67 | **HTTP 418**, страница «Forbidden / Сайт не работает с включённым VPN и блокировщиком рекламы» |
| напрямую | 94.25.111.192 | **HTTP 200**, нормальный сайт |

Решение: `session.fromPartition('persist:zvuk').setProxy({ mode: 'direct' })` до загрузки.
В приложении это настройка «обходить системный прокси» (по умолчанию включена).

## 3. Сайт в Electron рендерится нормально

Скриншот `_spike/stage1-home.png`: шапка, поиск, подборки, баннер «14 дней», cookie-баннер.
73 скрипта, 129 кнопок, SPA. Cookie-баннер закрывается кнопкой с текстом «Принять» —
сработало с первого раза.

## 4. Перехват mediaSession работает (механика подтверждена)

`webContents.debugger` → `Page.enable` → `Page.addScriptToEvaluateOnNewDocument` →
`window.__zs` существует, `errors: []`, `snapshot()` отдаёт JSON. То есть скрипт
действительно попадает в main world **до** скриптов сайта, и страница его не сносит.

Важно: пока не было воспроизведения, `handlers` пуст (`[]`), `metadata: null`,
`mediaCount: 0` — плеер и `<audio>` создаются не при загрузке страницы, а при старте трека.

## 5. Без аккаунта играть нельзя

На странице трека (`/track/5896627`, Metallica — Nothing Else Matters) кнопка «Слушать»
ведёт на `https://id.zvuk.com/?redirect_url=...`, то есть playback требует входа.
Сайт сам пытается авто-логин (`id.sber.ru/...machineClick=aggressivelogin`), без сессии
возвращается и получает 401 (в консоли: `GraphQL 401` → `starting token refresh`).
Значит для проверки воспроизведения нужен вход по Сбер ID — его делает человек.

Отдельно: ловушка для DOM-стратегии — кнопка «Слушать бесплатно» в нижнем промо-баннере
перехватила клик вместо кнопки плеера. Селектор должен искать в пределах плашки плеера
или проверять несколько кандидатов, а не первый по тексту.

## 6. Следующее (после входа)

1. Появились ли `handlers` (`play`, `pause`, `nexttrack`, `previoustrack`) и `<audio>`.
2. Идёт ли время (`currentTime` растёт) и слышен ли звук.
3. Работают ли `__zs.call('nexttrack'/'previoustrack'/'pause')` — то есть обработчики
   самого сайта, а не имитация клика.
4. `aria-label` плашки: «Пауза», «Следующий трек», «Предыдущий трек», «Нравится»
   и их `aria-pressed`.
5. `HiFi`: кнопка качества, как переключается и запоминается ли.

## 7. Мелкие факты, которые пригодятся

- Профиль держим в `persist:zvuk` (в спайке — `_spike/profile`), cookie переживают перезапуск.
- `--autoplay-policy=no-user-gesture-required` уже включён: после восстановления трека
  автоплей не потребует клика.
- Скриншоты со страницы снимаются через `webContents.capturePage()` — годится для
  диагностики «сайт обновился».
- Лог браузера пишем в файл: stdout GUI-процесса на Windows в пайп не попадает,
  без `boot.log` отладка слепая.

## 8. Итоги Ф0 на живом аккаунте (после входа)

Проверено на играющем альбоме Metallica (`/release/669414`), сессия сохранена и
пережила перезапуск приложения (в профиле `.zvuk.com: access_token`, `refresh_token`,
`auth`, `user_id`, `sa_subscription` — 55 cookie).

| Что | Результат |
|---|---|
| Воспроизведение в оболочке | **работает**, звук идёт |
| `mediaSession.setActionHandler` сайта | регистрирует только `play`, `pause`, `seekto` |
| `nexttrack` / `previoustrack` | **не регистрирует** — только DOM-клик |
| `navigator.mediaSession.metadata` | отдаёт трек, артиста, альбом и три URL обложки |
| `setPositionState` | **не вызывает** — позицию брать неоткуда, кроме элемента media |
| `<audio>` в DOM | нет; элемент создаётся вне DOM (MSE, `blob:`), найден хуком `HTMLMediaElement.play` |
| Позиция/длительность | из этого элемента: `currentTime`, `duration` (388 c = 6:28) |
| Кнопки плашки | **без aria-label и без текста**, только SVG-иконки |

Отсюда две поправки к плану:

1. **Позицию берём из перехваченного элемента media**, а не из `setPositionState`.
   В `injection.ts` хукается `HTMLMediaElement.prototype.play`, элемент складывается в
   `st.mediaEls`, даже если он не в документе. `positionState` оставлен вторым источником.
2. **DOM-стратегия для zvuk — по геометрии, а не по подписям.** Внутри контейнера
   `[class*="miniPlayerWrapper"]` транспорт — три кнопки 32×32, стоящие вплотную:
   `[0]` предыдущий, `[1]` play/pause, `[2]` следующий. Кнопку обложки (тоже 32×32,
   левее) обязательно исключать — из-за неё первый вариант кликал play/pause на `next`.
   Лайк — `[class*="btnAdd"]`, дизлайк — `btnDislike`, перемешать/повтор/очередь —
   `[class*="iconWrapper"]` по порядку.

Проверено на альбоме: next → Sad But True → Holier Than Thou, prev → назад, лайк
кликается (`how: btnAdd`). На странице одиночного трека next ничего не меняет —
в очереди один трек, это ожидаемо.

## 9. Меню на плашке

Нативное `Menu.popup({ window: barWin })` на этой машине **не всплывает** (frameless
always-on-top окно без фокуса; после `focus()` тоже молчит). Поэтому меню рисуется внутри
окна полосы: при открытии окно подрастает вверх на высоту пунктов, полоса остаётся внизу,
пункты те же, что в трее, плюс «Настройки…» и «Папка профиля».

⚠ Ловушка: обработчик `resize` возвращал окну высоту 35 px и «съедал» меню. Флаг
`menuOpen` теперь ставится **до** `setBounds`.

## 10. Диагностика без DevTools

Команды для отладки (файлы в `_diag/`): `command.txt` понимает `toggle`, `next`, `prev`,
`like`, `menu`, `nav:<url>` и `eval:<js>`; `state.json` пишется каждые 4 с — там URL,
имена cookie, снимок `mediaSession`, `positionState` и результат последнего DOM-клика
(`lastClick`: `how`/`reason`). Этого хватает, чтобы понять, какая стратегия сработала.
