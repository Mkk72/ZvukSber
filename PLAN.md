# ZvukSber — настольный плеер для zvuk.com (Звук, Сбер)

Рабочий план. Составлен 13.11.2026 по итогам проверки машины и разведки по zvuk.com.

---

## 1. Задача

Подписка на https://zvuk.com работает только в браузере. Нужно приложение для Windows,
которое держит плеер в своём окне (не в браузере), умеет ставить на паузу, переключать
треки, лайкать, сворачивается в трей и слушается мультимедийных клавиш.
Дополнительное пожелание — по возможности кроссплатформенность (Linux/macOS потом, не сейчас).

## 3. На чём писать

### Рекомендация: **Electron + TypeScript** (electron-vite + electron-builder)

| Вариант | Кроссплатформа | Оболочка сайта | Трей | Мультимедиа-клавиши | Моя скорость | Итог |
|---|---|---|---|---|---|---|
| **Electron + TS** | Win/Linux/macOS | свой Chromium — сайт ведёт себя как в Chrome | `Tray` из коробки | `globalShortcut('MediaPlayPause')` | высокая, есть образец | **выбран** |
| Tauri 2 (Rust) | Win/Linux/macOS | системный WebView2 / WebKitGTK / WKWebView | есть | нужен свой нативный слой | средняя | риск: WebKitGTK и тяжёлый SPA |
| Avalonia / .NET | Win/Linux/macOS | WebView2 только на Win, на Linux — CEF/WebKit | есть | WinRT-проекция | средняя | оболочка сайта разъезжается по платформам |
| Delphi (VCL/FMX) + EdgeView2 | только Win | WebView2 | `TTrayIcon` | WinAPI-хук | высокая | кроссплатформы нет, SMTC через WinRT в Delphi больно |
| WinUI 3 / WPF | только Win | WebView2 | есть | SMTC через WinRT | высокая | то же: только Windows |

Почему Electron, хотя Delphi мне тоже привычен:

1. **Кроссплатформенность бесплатно.** Один код — Windows, Linux, macOS. Delphi её не даёт вообще.
2. **Сайт — это SPA с плеером.** Electron несёт свой Chromium, поэтому zvuk.com в нём
   выглядит и звучит ровно как в Chrome. У Tauri на Linux WebKitGTK, и такой сайт там
   регулярно ломается; у Avalonia то же самое.
3. **Всё нужное — штатные API:** трей, single instance, автозапуск, глобальные хоткеи,
   внедрение скрипта до загрузки страницы (`webContents.debugger` + CDP), persistent-профиль с cookie.
4. **Есть живой образец** ([Desktop-ZvukApp](https://github.com/Bassbarlow/Desktop-ZvukApp)), то есть
   класс задачи известен, а не гипотетический.
5. Расплата — размер: ~100 МБ установщик вместо ~8 МБ у Tauri. Для домашнего плеера несущественно.

Если позже понадобится «нативный» оверлей Windows (Центр мультимедиа, кнопка на экране блокировки),
добавляется отдельный маленький Rust-аддон (napi-rs + `windows` crate) — Rust на машине есть.
Это не меняет основную кодовую базу.

### Чего делать не будем

- Не обходим DRM и не выдёргиваем поток через неофициальный API (`zvuk-music` умеет, но это
  против правил сервиса и ломается от любого их релиза). Подписка остаётся, играет официальный
  плеер внутри нашего окна — это принципиально другой риск, чем «клиент на реверс-API».
- Не делаем скачивание треков и обход региональных ограничений.

## 4. Как это будет работать

### Оболочка

`BrowserWindow` без меню, грузит `https://zvuk.com/`, профиль в `%APPDATA%\ZvukSber\profile`
(cookie и вход переживают перезапуск). Наша тонкая рамка: кнопка «в трей», кнопка мини-плеера,
заголовок «Артист — Трек».

### Управление плеером — три стратегии, выбор на ходу

Управлять сайтом можно тремя способами, надёжность падает сверху вниз. Реализуем все три,
переключение автоматическое + ручное в настройках.

1. **Перехват `navigator.mediaSession` (основной).**
   Скрипт внедряется в main world **до** скриптов страницы через
   `webContents.debugger` → `Page.addScriptToEvaluateOnNewDocument`. Он оборачивает
   `mediaSession.setActionHandler` и `setPositionState`: обработчики сайта складываются в
   `window.__zs.handlers`, метаданные (`title/artist/album/artwork`) и позиция — в `window.__zs.state`.
   Дальше main-процесс: читает состояние опросом (~4 раза в секунду, дёшево) и вызывает
   `window.__zs.handlers['nexttrack']()` — то есть **код самого сайта**, а не имитацию клика.
   Это самый устойчивый путь: mediaSession — стандарт, его не переименуют при редизайне.
2. **DOM-клик по `aria-label`** («Пауза», «Следующий трек», «Предыдущий трек», «Нравится»).
   Fallback, если обработчики не зарегистрированы. Селекторы в одном файле, правятся за минуту.
3. **Синтетические клавиши** (`Space`, `Ctrl+→`) — последний резерв.

«Лайк» через mediaSession не выражается (такого действия в стандарте нет), поэтому он всегда
идёт по DOM-кнопке `Нравится` с проверкой `aria-pressed`, а состояние подтягивается в трей.

### Что именно контролируем — инвентарь по плашке zvuk.com

Плашка сайта (по присланному скриншоту) состоит из двух рядов. Разбор по элементам:
верхний ряд — обложка, «Larmes» с меткой «explicit», «L2Haine», таймер `0:17`, дизлайк,
⏮, ⏸, ⏭, ♥; нижний — громкость, перемешать, повтор, очередь, кнопка `HiFi`.

| Элемент | Действие mediaSession | DOM-fallback (`aria-label`) | Где у нас |
|---|---|---|---|
| Обложка, трек, артист, таймер | `metadata` + `setPositionState` | — | заголовок окна, тултип трея, мини-плеер |
| ⏮ | `previoustrack` | «Предыдущий трек» | трей, хоткей, SMTC, мини-плеер |
| ⏯ | `play` / `pause` | «Пауза» / «Воспроизвести» | везде |
| ⏭ | `nexttrack` | «Следующий трек» | везде |
| ♥ | **в стандарте нет** | «Нравится» + `aria-pressed` | трей, хоткей, мини-плеер |
| дизлайк | **нет** | «Не нравится» | только мини-плеер (опционально) |
| громкость | нет (её и не надо трогать) | слайдер | остаётся сайту; при желании — колесо/хоткей |
| перемешать | **нет** | «Перемешать» + `aria-pressed` | в трее флагом, в мини-плеере кнопкой |
| повтор | **нет** | «Повторить» (выкл / всё / один) | в трее пунктом с подменю |
| очередь | **нет** | «Очередь воспроизведения» | кнопка «показать панель очереди» в мини-плеере |
| `HiFi` | нет | кнопка качества | индикатор качества в тултипе; переключение — в настройках |

Вывод: из десяти элементов плашки через `mediaSession` проходят только четыре (⏮ ⏯ ⏭ и
метаданные с позицией). Остальное — DOM. Поэтому `DomBridge` — не «резерв на всякий случай»,
а обязательная часть с первого дня, просто вторичная по приоритету: сначала пробуем
`mediaSession`, затем DOM, и в диагностике видно, что сработало.

### Мини-плеер — две формы, обе без рамки, always-on-top, не забирают фокус

Форма 1 — **полоса 35 px** (как панель foobar2000), основная. Высота окна ровно **≤ 35 px**:

```
┌───────────────────────────────────────────────────────────────┐
│ [28] Larmes — L2Haine        ⊘  ⏮  ⏸  ⏭  ♥          0:17/3:49 │  ← высота 34 px
│▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂▂│  ← 2 px прогресс
└───────────────────────────────────────────────────────────────┘
```

- обложка 28×28, название и артист в одну строку (при нехватке места — прокрутка),
- кнопки 24 px: дизлайк, ⏮, ⏸/▶, ⏭, ♥,
- прогресс — линия 2 px по нижнему краю окна, не отдельный элемент,
- ширина от 300 px до ширины экрана, запоминается; в настройках «поверх всех окон» и
  «прилипать к краю экрана».

Форма 2 — **широкая плашка ~420×110**, две строки, как на присланном скриншоте:
обложка, трек/артист/таймер, ряд кнопок; внизу громкость, перемешать, повтор, очередь, HiFi.

```
┌──────────────────────────────────────────────────────┐
│ [обл.] [!] Larmes          ⊘   ⏮   ⏸   ⏭   ♥        │
│        L2Haine   0:17                                 │
│  ──────────────────────────────────────────────       │
│  🔊 ────●─   ⤨   ⟲   ☰   [ HiFi ]                     │
└──────────────────────────────────────────────────────┘
```

Обе формы — один код контроллера и одна модель состояния, различаются только вёрсткой
(и запоминанием размера/позиции отдельно на каждую). Прогресс берём из состояния плеера
сайта, а не из собственного таймера: иначе расходится после буферизации.

### Приличный плеер снаружи

| Что | Windows | Linux/macOS |
|---|---|---|
| Трей: play/pause, next, prev, лайк, «Показать окно», «Выход»; подсказка «Артист — Трек» | `Tray` | `Tray` (+ нужен libappindicator) |

| Горячие клавиши настраиваемые (Ctrl+Alt+…) | есть | есть |

### Логика отдельно от UI (правило из моей памяти, соблюдаем сразу)

Ядро — чистый TypeScript без единого импорта Electron, покрыто vitest:

```
src/core/            # headless: тестируется без окна
  playerState.ts     # модель: трек, статус, позиция, лайк, доступность команд
  commands.ts        # PlayerCommand → разрешена ли команда сейчас, дебаунс, повтор
  mediaMetadata.ts   # сырой mediaSession.metadata → TrackInfo (нормализация, пустые поля)
  commandSource.ts   # откуда пришло: трей / хоткей / SMTC / мини-плеер — единый вход
  trayMenuModel.ts   # модель меню трея (пункты, галочки) без самого Tray
src/main/            # адаптеры Electron, тонкие
  index.ts           # сборка приложения, single instance
  windowShell.ts     # реализует IPlayerView
  trayAdapter.ts     # реализует ITrayView по модели из core
  presenter.ts       # PlayerPresenter: core + интерфейсы представлений
  bridge/            # IMediaBridge: MediaSessionBridge | DomBridge | KeyboardBridge
  settings.ts        # настройки (JSON в userData)
src/preload/         # то, что видит страница (DOM-наблюдатель, обложка, audio element)
src/renderer/        # наша оболочка: мини-плеер, настройки, диагностика
test/                # vitest на core + presenter с фейковыми view
```

Проверка приёмки та же, что в RTI: «можно ли это протестировать без окна?» Если нет — логика
утекла в UI, переделываем.

### Вход в аккаунт

WebView (Chromium) с обычным UA — Sber ID логинится внутри окна, сессия в профиле. Риск: Sber ID
может не любить встроенные браузеры. Обходы по порядку: подмена UA на Chrome, затем
`shell.openExternal` и импорт cookie из системного браузера (Chromium-профиль, тот же формат),
затем ручной ввод cookie. Проверяется в фазе 0 — это второй по важности вопрос после playback.

## 5. План по фазам

Каждая фаза заканчивается работающим состоянием и проверкой; после фазы 0 — решение «идём/нет».

### Ф0. Спайк, 0.5 дня — снимаем риски, а не пишем продукт
- `electron-vite` скелет, окно грузит `zvuk.com`.
- Вход в аккаунт по подписке внутри окна.
- **Включается ли музыка и слышно ли её** (главный вопрос: EME/DRM, автоплей, звук).
- Внедрение перехватчика `mediaSession`: доходят ли `play/pause/nexttrack/previoustrack`
  и `metadata` (обложка, артист).
- Проверка DOM-кнопки «Нравится», реакция на `Space`.
- Проверка `globalShortcut` на MediaPlayPause при свёрнутом окне.
- Итог: короткая записка в `NOTES-spike.md` с фактами «работает / не работает / чем заменили».

**Приёмка:** музыка играет, next/prev/пауза управляются из main-процесса, метаданные читаются.
Если playback не заработал — стоп и обсуждение альтернативы (Edge в app-режиме + контроллер),
а не имитация прогресса.

### Ф1. Каркас и ядро, 1 день
- Структура из §4, `core` + `presenter` + фейковые view, vitest зелёный.
- Single instance, сохранение размера/позиции окна, настройки в `userData`.
- Наша рамка окна, заголовок «Артист — Трек», состояние «нет входа / играет / пауза».

**Приёмка:** `npm test` зелёный, приложение запускается и переживает рестарт с тем же профилем.

### Ф2. Управление как у плеера, 1.5 дня
- `MediaSessionBridge` (CDP-инъекция), `DomBridge`, `KeyboardBridge` + автопереключение.
- Трей: меню, подсказка с треком, двойной клик — показать/скрыть, закрытие в трей.
- Мультимедиа-клавиши и настраиваемые хоткеи, лайк из трея.

**Приёмка:** окно свёрнуто в трей → клавиша паузы на клавиатуре работает; смена трека в сайте
сама обновляет подсказку трея; лайк из трея отражается в сайте.

### Ф3. Привычки приличного плеера, 1 день
- Мини-плеер в двух формах: полоса **35 px** (основная) и широкая плашка ~420×110;
  переключение формы в трее, размер и позиция запоминаются на каждую форму отдельно.
- Автозапуск, «стартовать свёрнутым», отключение медиа-клавиш.
- Диагностика: страница «что нашлось» — какая стратегия активна, какие `aria-label` найдены,
  лог ошибок инъекции. Это то, что спасает после редизайна сайта.
- Обработка «сайт обновился, управление не найдено»: человеческое сообщение, а не тихий отказ.

**Приёмка:** сценарий «свернул в трей, слушаю час, переключаю с клавиатуры, лайкаю» проходит
без открытия окна.

### Ф4. Упаковка, 0.5 дня
- `electron-builder`: Windows NSIS + portable, иконки, версия, подпись не нужна.
- Проверка на чистом профиле: установка → вход → играет.
- README: как запустить, где настройки, что делать при поломке управления.

**Приёмка:** установщик ставится и работает на этой машине с нуля.

### Ф5 (опционально). Windows-оверлей мультимедиа
- Rust-аддон napi-rs → `SystemMediaTransportControls`: обложка, название, прогресс,
  кнопки в оверлее Windows и на экране блокировки, аппаратные клавиши без захвата.

### Ф6 (опционально). Linux/macOS
- Сборки AppImage/deb, MPRIS на Linux, `MPNowPlayingInfoCenter` на macOS (нужна подпись,
  иначе macOS ругается). Код оболочки уже кроссплатформенный, здесь только сборочные таргеты.

Итого обязательное: **~4.5 дня** моей работы фазами с проверкой после каждой; факультатив — ещё 2–3.

## 6. Риски и что делаем

| Риск | Вероятность | Решение |
|---|---|---|
| Звук не пойдёт из-за EME/DRM в оболочке | низкая (потоки — mp3/flac), проверяем в Ф0 | Electron с CDM от castlabs, либо Edge в app-режиме под управлением нашего трея |
| Sber ID не пускает встроенный браузер | средняя | UA как Chrome, затем `openExternal` + импорт cookie, затем ручной ввод |
| Редизайн сайта ломает DOM-селекторы | высокая со временем | основная стратегия — mediaSession, а не DOM; страница диагностики; селекторы в одном файле |
| Медиа-клавиши перехватывает сам Chromium/другое приложение | средняя | `globalShortcut` + отключаемый флаг, проверка в Ф2 |
| Трей на Linux требует libappindicator | высокая (когда дойдём) | отметить в README, graceful degradation |
| Сборка/`npm i` падают в песочнице | факт (проверено) | работаю с `danger-full-access`, иначе не собирается |
| Правила сервиса | — | играет официальный плеер, DRM и API не трогаем |
